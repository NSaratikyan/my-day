# Իմ օրը

## Շաբաթական կրկնություն (1.1.0)

Առաջադրանքի ձևի «Կրկնություն» բաժնում ընտրեք շաբաթների քանակը, ամիսների քանակը, ավարտի ամսաթիվը կամ «մինչև անջատելը»։ Կրկնվում է առաջին ընտրված ամսաթվի շաբաթվա նույն օրը։ Երկու շաբաթը ներառում է առաջին առաջադրանքը՝ ընդհանուր երկու հանդիպում։ Ամիսները օրացուցային են՝ սկզբից մինչև համապատասխան ամսաթվի նախորդ օրը, իսկ ձեռքով ընտրված ավարտի օրը ներառական է։

Յուրաքանչյուր շաբաթն ունի իր կարգավիճակը։ Մեկ օրվա անվանման, ժամի կամ նշման փոփոխությունը չի փոփոխում ամբողջ շարքը։ Կրկնության տևողության կարգավորումը վերաբերում է ամբողջ շարքին՝ սկզբնական ամսաթվից։ Ջնջված կամ տեղափոխված հանդիպումը կրկին չի ստեղծվում։ «Ավելին → Կրկնվող առաջադրանքներ»-ից կարելի է անջատել կամ միացնել շարքը։ Անջատելիս հեռացվում են ապագա նախատեսված կրկնությունները, պահպանվում են անցած և կատարված առաջադրանքները։ Խմբագրման ձևից անջատելիս պահպանվում է նաև խմբագրվող առաջադրանքը։

Առաջադրանքները սարքում ստեղծվում են մեկ տարի առաջ, և ցանկը երկարացվում է հավելվածը բացելիս, ակտիվ օգտագործելիս ու շաբաթներով առաջ անցնելիս։ Փակ հավելվածը ֆոնային աշխատանք չի պահանջում։ Բազայի v2 migration-ը պահպանում է հին տվյալները։ JSON պահուստի v2-ը ներառում է կրկնությունները, իսկ հին v1 պահուստները շարունակում են ներմուծվել։

Հրապարակված նոր տարբերակը ստանալու համար բացեք հավելվածը ինտերնետով և սեղմեք «Թարմացնել» առաջարկը։ Նախ պահպանեք բաց ձևը։ Նորից տեղադրել պետք չէ։ Տվյալները մնում են նույն սարքում և նույն կայքի հասցեի տակ։

GitHub նախագիծ՝ [NSaratikyan/my-day](https://github.com/NSaratikyan/my-day)։ Սկզբնական նկարագրություն՝ «My day planing»։

Հայերեն, mobile-first օրվա պլանավորման PWA՝ առանց գրանցման, backend-ի և արտաքին API-ների։ Առաջադրանքները, կատեգորիաները, կարգավորումներն ու օրական նշումները պահվում են տվյալ սարքի IndexedDB-ում։

## Գործարկում

Պահանջվում է Node.js 22.12+ և npm։ Նախագծի արմատային պանակում՝

```sh
npm install
npm run dev
```

Բացեք development server-ի ցուցադրած հասցեն (սովորաբար http://localhost:5173)։

Այս Windows workspace-ում կարող եք նաև գործարկել `.\start.cmd`։ Այն գտնում է արդեն տեղադրված Node.js-ը կամ Codex-ի ներկառուցված միջավայրը։ `.\start.cmd verify`-ն հաջորդաբար գործարկում է lint-ը, թեստերն ու build-ը, իսկ `.\start.cmd preview`-ն բացում է production preview server-ը։

```sh
npm run lint
npm test
npm run build
npm run preview
```

Production արդյունքը `dist/` պանակում է։ Preview հասցեն սովորաբար http://localhost:4173 է։ Service worker-ը միացված է production build-ում, որպեսզի development-ի ընթացքում հին ֆայլերը չխանգարեն։

## Տեխնոլոգիաներ և կառուցվածք

- React 19, TypeScript strict, Vite, React Router
- Dexie / IndexedDB, schema v1, dexie-react-hooks
- vite-plugin-pwa / Workbox՝ manifest, offline app shell և թարմացման առաջարկ
- Lucide պատկերակներ, CSS variables՝ համակարգային, բաց և մուգ թեմաներով
- FormatJS-ի ներկառուցված հայերեն օրացուցային տվյալներ՝ նաև հայերեն locale չպարունակող դիտարկիչների համար։ Ժամային հաշվարկները շարունակում են օգտագործել սարքի տեղական ժամային գոտին։
- Zod՝ պահուստային պատճենների ամբողջական ստուգում
- Vitest, React Testing Library, fake-indexeddb

Հիմնական ֆայլերը՝

- `src/config.ts` — հավելվածի անունը, տարբերակն ու բազայի անունը։ Անվան բոլոր ցուցադրումները և manifest-ը վերցնում են նույն configuration-ից։
- `src/model.ts` — տիպեր, տեղական ամսաթվեր, առաջընթաց, validation, պահուստային schema։
- `src/db.ts` — schema versioning, transaction-ներով պահպանում, արտահանում/ներմուծում։ Հետագա migration-ները ավելացրեք `version(2)` և հաջորդ տարբերակներով։
- `src/pages/` — Այսօր, Շաբաթ, առաջադրանքի ձև, Նշումներ, Ավելին։
- `src/components.tsx` — ընդհանուր առաջադրանքի քարտ, օրերի ընտրություն և առաջընթաց։
- `src/pwa.tsx` — տեղադրում, թարմացումներ, ծանուցումների առաքման ինտերֆեյս։
- `src/styles.css` — responsive միջերես, 320 px-ից մինչև կենտրոնացված desktop։
- `src/test/` — գործառնական և ձևի թեստեր։
- `public/` — 192 և 512 px PNG պատկերակներ և maskable պատկերակ։

Build-ի համար օգտագործվում է esbuild-ի WebAssembly տարբերակը՝ Windows-ի սահմանափակ միջավայրերում նույն կերպ աշխատելու համար։ Սա չի ազդում պատրաստի հավելվածի արագության կամ offline աշխատանքի վրա։

## Հեռախոսի վրա տեղադրում

### GitHub Pages — պատրաստված տարբերակ

Այս repository-ի համար հասցեն կլինի **https://nsaratikyan.github.io/my-day/**՝ միայն հաջող հրապարակումից հետո։

1. Վերբեռնեք նախագծի սկզբնաղբյուրները repository-ի արմատում։ Կարևոր է պահպանել պանակների կառուցվածքը, ներառյալ `.github/workflows/pages.yml`-ը։ Մի վերբեռնեք `node_modules/`, `work/`, `outputs/` կամ ձեր անձնական JSON պահուստները։
2. GitHub-ում բացեք **Settings → Pages → Build and deployment → Source → GitHub Actions**։
3. `main` branch-ում փոփոխության պահպանումը ինքնուրույն կգործարկի **Publish My Day** workflow-ը։ Կարող եք նաև բացել **Actions → Publish My Day → Run workflow**։
4. Workflow-ը կատարում է `npm ci`, lint, բոլոր թեստերը, GitHub Pages build-ը և ստուգում է ստեղծված ֆայլերի հասցեները։ Միայն դրանից հետո այն հրապարակում է `dist/` պանակը։
5. Երբ build և deploy փուլերը կանաչ են, բացեք վերևի HTTPS հասցեն հեռախոսում և հետևեք ստորև տրված տեղադրման քայլերին։

GitHub Pages-ի տարբերակը օգտագործում է hash նավիգացիա․ օրինակ՝ `/my-day/#/notes`։ Սա թույլ է տալիս առաջին այցելությունը, էջի refresh-ը և ուղիղ հղումները՝ առանց սերվերի հատուկ SPA կարգավորման։ Manifest-ի, պատկերակների և service worker-ի բոլոր հասցեներն ու scope-ը սահմանափակված են `/my-day/` պանակով։

Տեղական ստուգում՝

```sh
npm run build:pages
npm run preview:pages
```

Բացեք **http://localhost:4180/my-day/**։ Windows-ում համարժեք հրամաններն են `.\start.cmd verify:pages` և `.\start.cmd preview:pages`։ Սովորական `npm run build`-ը շարունակում է ստեղծել արմատային `/` հասցեի տարբերակը։ Վերջին գործարկված build-ն է գտնվում `dist/` պանակում։

GitHub-ի անվճար հրապարակային repository-ում ծրագրի կոդը և կայքը հանրային են։ Առաջադրանքներն ու նշումները մնում են յուրաքանչյուր այցելուի սարքում և չեն հայտնվում repository-ում։ Համակարգչից հեռախոս տեղափոխելու համար օգտագործեք հավելվածի JSON արտահանումը և ներմուծումը։

Աղբյուրներ՝ [GitHub Pages workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [Vite-ի GitHub Pages ուղեցույց](https://vite.dev/guide/static-deploy.html#github-pages)։

### Android և iPhone

Հեռախոսում տեղադրելու համար production build-ը մատուցեք HTTPS հասցեով։ Պարզ HTTP հասցեով տեղական ցանցից բացելը լիարժեք PWA տեղադրման պայմաններին չի բավարարում։ `localhost` բացառությունն աշխատում է միայն նույն սարքում։ Հոսթինգը պետք է բոլոր հավելվածային երթուղիները վերադարձնի `index.html`-ին (SPA fallback)։ Առաջին բացման համար ինտերնետ է անհրաժեշտ։

**Android․** Chrome-ում բացեք HTTPS հասցեն։ «Ավելին» բաժնի «Տեղադրել հավելվածը» կոճակը ցուցադրվում է, եթե դիտարկիչը տրամադրել է install prompt։ Կարող եք նաև Chrome-ի մենյուից ընտրել տեղադրումը կամ գլխավոր էկրանին ավելացնելը։

**iPhone․** Safari-ում բացեք HTTPS հասցեն → Share → Add to Home Screen → Add։

Տեղադրումից հետո հավելվածը բացվում է առանձին պատուհանով։ Առաջադրանքների և նշումների հիմնական գործողությունները կատարվում են առանց ինտերնետի։ Նոր տարբերակի դեպքում ցուցադրվում է «Թարմացնել» առաջարկը։ Նախ ավարտեք բաց ձևի լրացումն ու պահպանումը, ապա թարմացրեք։

## Տվյալներ և պահուստավորում

Տվյալները կապված են տվյալ սարքի, դիտարկիչի և կայքի հասցեի հետ։ Դրանք ինքնաբերաբար չեն փոխանցվում այլ սարք։ Դիտարկիչի տվյալների մաքրումը կամ կայքի հասցեի փոփոխությունը կարող է անհասանելի դարձնել տեղական գրառումները։ Պարբերաբար արտահանեք JSON պահուստային պատճենը «Ավելին» բաժնից։ Ֆայլը պարունակում է ձեր նշումները, ուստի պահեք ձեր ընտրած անվտանգ վայրում։

Ներմուծումը նախ ստուգում է բոլոր դաշտերը, ամսաթվերը, կապերը, կրկնվող id-ները և օրվա առավելագույն երեք գլխավորները։ Այնուհետև պահանջում է ամբողջ ընթացիկ տվյալները փոխարինելու հաստատում։ Սխալ ներմուծման դեպքում տվյալները չեն փոխվում։ Առավելագույն ֆայլի չափը 20 ՄԲ է։ Մաքրման գործողությունը նույնպես պահանջում է հաստատում և վերականգնում է սկզբնական ինը կատեգորիաները։

Ամսաթիվը պահպանվում է `YYYY-MM-DD`, ժամը՝ `HH:mm` ձևով։ Հաջորդ օրը հաշվվում է տեղական օրացույցով, առանց UTC փոխարկման։ «Տեղափոխել վաղվան»-ը նշանակում է առաջադրանքի նշված ամսաթվին հաջորդող օրը։ Օրինակ՝ սեպտեմբերի 10-ի առաջադրանքը տեղափոխվում է սեպտեմբերի 11՝ նույնիսկ եթե այսօր այլ օր է։

Չեղարկվածները չեն մասնակցում առաջընթացի հաշվարկին։ Գլխավոր լինելու սահմանափակումը գործում է բոլոր կարգավիճակների համար. չորրորդ ընտրության դեպքում պետք է փոխարինել առկա գլխավորներից մեկին։ Կատարվածը կրկին սեղմելիս վերականգնվում է նախորդ կարգավիճակը։

## Նշումների ավտոպահպանում

Նշումները պահվում են մուտքագրումից մոտ 450 մվ անց, դաշտից դուրս գալիս և էջից հեռանալիս։ Սխալները ցուցադրվում են պահպանման կարգավիճակի կողքին։ Սպասեք «Փոփոխությունները պահպանված են» հաղորդագրությանը՝ հավելվածը հարկադիր փակելուց առաջ։

## Հիշեցումների սահմանափակում

1.2.1 տարբերակում առաջադրանքի «Հիշեցում» դաշտը ներառում է «Մեկնարկի պահին» ընտրանքը։ «Անջատված»-ը նախկինի պես չի ուղարկում հիշեցում՝ նույնիսկ լրացված ժամի դեպքում։ «Ավելին» բաժնում միացրեք համակարգային թույլտվությունը, ապա սեղմեք «Փորձնական ծանուցում»։ Արգելափակված թույլտվությունը փոխվում է դիտարկիչի/հեռախոսի կարգավորումներից։ Ուղարկման սխալներն այլևս լուռ չեն անտեսվում։

Բաց հավելված վերադառնալիս հիշեցումը կարող է ցուցադրվել մինչև մեկնարկից 15 րոպե անց։ Սա բաց թողնված ժամի կարճ լրացում է, ոչ փակ հավելվածում աշխատող ժամանակացույց։ Նախապես ուղարկված նույն հիշեցումը մեկնարկին երկրորդ անգամ չի ուղարկվում։

Հիշեցման կարգավորումը պահպանվում է առաջադրանքի հետ։ Բաց կամ ակտիվ հավելվածում ժամերը ստուգվում են 15 վայրկյանը մեկ։ Notification API-ի թույլտվությունը հարցվում է միայն օգտատիրոջ սեղմումից հետո։ Նույն առաջադրանքի համակարգային հիշեցումը տվյալ նստաշրջանում կրկնակի չի ցուցադրվում։

Փակ հավելվածի background notification-ը չի երաշխավորվում։ Այս տարբերակը չունի push server կամ օպերացիոն համակարգի հուսալի ժամանակացույց։ iOS-ի և այլ հարթակների թույլտվություններն ու սահմանափակումները կարող են տարբեր լինել։ Ներհավելվածային հիշեցումները չեն պահանջում համակարգային թույլտվություն։

## Օրվա հորոսկոպը (1.2.0)

«Ավելին» → «Ծննդյան ամսաթիվ և հորոսկոպ» բաժնում ընտրեք ամսաթիվը և պահպանեք։ «Այսօր» էջի ողջույնի տակ կերևան նշանն ու ամենօրյա խորհուրդը։ Ամսաթիվը կարելի է փոխել կամ հեռացնել նույն կարգավորումից։ Այն պահվում է IndexedDB-ում և ներառվում է JSON պահուստային պատճենում։ Առանց այդ դաշտի հին պատճեն ներմուծելիս ծննդյան կարգավորումը կմաքրվի։

Կիրառվում են արևմտյան արևային նշանների ընդունված [ամսաթվային սահմանները](https://www.astrology.com/article/zodiac-sign-dates/)։ Ծննդյան ժամն ու վայրը չեն հաշվարկվում. սահմանային օրերին սա ճշգրիտ ծննդյան քարտեզ չէ։ Խորհուրդները հավելվածի համար գրված ժամանցային տեքստեր են, ոչ արտաքին ծառայության ընթացիկ կանխատեսումներ։ 31 խորհուրդների հավաքածուն հերթափոխվում է ըստ տեղական օրվա ու նշանի, ուստի ժամանակի ընթացքում տեքստերը կրկնվում են։ Նույն օրվա ընթացքում խորհուրդը կայուն է, հաջորդ օրը փոխվում է նաև անցանց։

Թարմացման համար բացեք տեղադրված հավելվածը ինտերնետով և սեղմեք «Թարմացնել», երբ առաջարկը հայտնվի։ Վերատեղադրում պետք չէ, տեղական առաջադրանքներն ու նշումները պահպանվում են։

## Հետագա զարգացում

Ըստ անհրաժեշտության՝ ավելացնել ընտրովի cloud sync, սարքերի միջև կոնֆլիկտների լուծում և իրական Web Push ծառայություն։ `ReminderDelivery` ինտերֆեյսը թույլ է տալիս փոխել ծանուցումների առաքման եղանակը։ Առաջին տարբերակը չի ուղարկում տվյալներ արտաքին ծառայությունների։
